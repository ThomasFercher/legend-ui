# Nomo UI Kit — Rewrite

This branch (`rewrite`) is the **active development branch** for the full rewrite of Nomo UI Kit. It shares no history with the legacy code.

| Branch | Contents |
|---|---|
| `rewrite` (this) | The new kit — Dart workspace, implementation in progress |
| `legacy-docs` | Complete documentation of the legacy codebase + the accepted design RFC |
| `main` | The legacy kit (v0.0.36), **frozen** as reference |

## Design

The architecture is fixed by the accepted RFC — read [docs/DESIGN.md](docs/DESIGN.md) before writing code. The one-paragraph version:

Design tokens (`NomoTokens`) are the only global theme. Component themes are **declared with decorators on the widget** (`@NomoThemeable` / `@Themed`) and their plumbing is generated by the **`nomo_gen` standalone CLI** (decided over build_runner). `NomoThemeData` is an **open, Type-keyed registry**, so package consumers can annotate *their own* widgets and get identical theming support — same decorators, same generated artifacts, same four-level resolution chain (constructor param → subtree override → app theme → token-derived defaults). Components are thin compositions over five primitives (surface, interactive, overlay engine, text core, field core).

## Workspace layout

```
packages/
  nomo_ui_kit/     # the kit (Flutter package)
  nomo_gen/        # the CLI (pure Dart, published for consumers)
example/           # gallery app — living docs + consumer-workflow reference
docs/DESIGN.md     # the accepted RFC (canonical copy also on legacy-docs as 09-rewrite-proposal.md)
ROADMAP.md         # phased plan with current status
```

Planned additions: `packages/nomo_gen_builder` (optional thin build_runner wrapper), `packages/nomo_icons` (optional FontAwesome package).

## What exists today

- **Tokens & theming**: `NomoTokens` (colors/sizes/typography/shadows), `NomoThemeData` open registry, `AnimatedNomoTheme` (one token lerp per theme switch), `NomoBreakpoints`.
- **Primitives**: `NomoSurface`, `NomoInteractive`, `NomoButtonCore`, `NomoAnchoredOverlay`, `NomoModalRoute`/`showNomoModal`.
- **Components**: Primary/Secondary/Text buttons, `NomoText`, `NomoTextField`, `NomoDropdown`, `NomoSwitch`, `NomoCard`, `NomoDialog`/`showNomoDialog`, `NomoDivider`, `NomoExpandable`, `NomoInfoItem`, `NomoContextMenu`.
- **Forms**: `NomoForm`/`NomoFormController`, `NomoFormField<T>`, `NomoValidators` — fields register/unregister with their lifecycle.
- **Feedback**: `showNomoToast` (queued, overlay engine), `NomoLoading`, `NomoShimmer`.
- **Shell**: `NomoApp`, `NomoScaffold`, `NomoAppBar`, `NomoSider`, `NomoBottomBar` — chrome flips by breakpoint tier.
- **Codegen**: `nomo_gen themes` (generate/`--check`/`--watch`), `nomo_gen create`, `nomo_gen doctor` — golden-tested; consumers annotate their own widgets and register them in the same theme map as kit components.

## Getting started

```bash
flutter pub get                          # resolves the whole workspace from the root
cd example && flutter run -d chrome      # component gallery
cd packages/nomo_ui_kit && dart run nomo_gen themes lib   # regenerate themes
```

Quality gates: `dart format`, `flutter analyze` (very_good_analysis), tests per package, and the `nomo_gen --check` freshness gate — all wired into `.github/workflows/ci.yml`.
