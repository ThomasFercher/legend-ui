A Material-free Flutter UI kit built on design tokens, decorator-declared component themes, and a standalone codegen CLI — configurable at every level, with good defaults at the bottom.

This branch (`rewrite`) is the **active development branch** for Legend UI — the full rewrite of the legacy Nomo UI Kit. It shares no history with the legacy code.

| Branch | Contents |
|---|---|
| `rewrite` (this) | Legend UI — Dart workspace, implementation in progress |
| `legacy-docs` | Complete documentation of the legacy codebase + the accepted design RFC |
| `main` | The legacy kit (nomo_ui_kit v0.0.36), **frozen** as reference |

## Design

The architecture is fixed by the accepted RFC — read [docs/DESIGN.md](docs/DESIGN.md) before writing code. The one-paragraph version:

Design tokens (`LegendTokens`) are the only global theme. Component themes are **declared with decorators on the widget** (`@LegendThemeable` + typed `@Style<T>` field defaults) and their plumbing is generated by the **`legend_gen` standalone CLI** (decided over build_runner). `LegendThemeData` is an **open, Type-keyed registry**, so package consumers can annotate *their own* widgets and get identical theming support — same decorators, same generated artifacts, same four-level resolution chain (constructor param → subtree override → app theme → token-derived defaults). Components are thin compositions over five primitives (surface, interactive, overlay engine, text core, field core).

In flight: [docs/RFC-002-DERIVED-DEFAULTS.md](docs/RFC-002-DERIVED-DEFAULTS.md) (**accepted**) — seed-derived tokens, the typed `@Style<T>` contract, generator-absorbed ceremony, and the CLI quality pass are landed (§5 steps A/B/A2/C/C2); the manifest-driven playground CMS (D) and custom style classes + granular rebuilds (E) are in progress. Proposed next: [docs/RFC-003-LEGEND-BODY.md](docs/RFC-003-LEGEND-BODY.md) — `LegendBody` page archetypes + `LegendSliver*` helpers.

## Workspace layout

```
packages/
  legend_ui/       # the kit (Flutter package)
  legend_gen/      # the CLI (pure Dart, published for consumers)
example/           # docs site + live theme playground — also the consumer-workflow reference
docs/DESIGN.md     # the accepted RFC (canonical copy also on legacy-docs as 09-rewrite-proposal.md)
ROADMAP.md         # phased plan with current status
```

Planned additions: `packages/legend_gen_builder` (optional thin build_runner wrapper), `packages/legend_icons` (optional FontAwesome package).

## What exists today

- **Tokens & theming**: `LegendTokens` (colors/sizes/typography/shadows/state overlays), `LegendTokens.fromSeed` (`LegendSeed` + AntD-adapted ramp, contrast-guaranteed pairs), `LegendThemeData` open registry, `AnimatedLegendTheme` (one token lerp per theme switch), `LegendBreakpoints`.
- **Primitives**: `LegendSurface`, `LegendInteractive`, `LegendButtonCore`, `LegendAnchoredOverlay`, `LegendModalRoute`/`showLegendModal`.
- **Components**: Primary/Secondary/Text buttons, `LegendText`, `LegendTextField`, `LegendDropdown`, `LegendSwitch`, `LegendCard`, `LegendDialog`/`showLegendDialog`, `LegendDivider`, `LegendExpandable`, `LegendInfoItem`, `LegendContextMenu`.
- **Forms**: `LegendForm`/`LegendFormController`, `LegendFormField<T>`, `LegendValidators` — fields register/unregister with their lifecycle.
- **Feedback**: `showLegendToast` (queued, overlay engine), `LegendLoading`, `LegendShimmer`.
- **Shell**: `LegendApp`, `LegendScaffold`, `LegendAppBar`, `LegendSider`, `LegendBottomBar` — chrome flips by breakpoint tier.
- **Codegen**: `legend_gen themes` / `docs` / `tokens` (each with `--check` for CI and a never-crash `--watch`), plus `create`, `doctor`, `update`, and shell completion — golden-tested; consumers annotate their own widgets and register them in the same theme map as kit components. Doc comments double as the theme-docs CMS via generated `*.docs.g.dart` manifests.
- **Docs & playground**: the `example/` app is a documentation site with live demos per component group, an interactive four-level resolution ladder, and a theme configurator (presets, brand colors, per-component overrides) — selectable text on web included.

## Getting started

```bash
flutter pub get                          # resolves the whole workspace from the root
cd example && flutter run -d chrome      # docs site + playground
```

```bash
dart format . && flutter analyze         # lint gate (very_good_analysis)
cd packages/legend_ui && flutter test    # kit test suite
cd packages/legend_gen && dart test      # generator test suite (incl. goldens)
cd example && flutter test               # docs-site behavior tests
cd packages/legend_ui && dart run legend_gen themes lib test/consumer   # regenerate committed themes
```
