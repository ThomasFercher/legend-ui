# Nomo UI Kit — Rewrite

This branch (`rewrite`) is the **active development branch** for the full rewrite of Nomo UI Kit. It shares no history with the legacy code.

| Branch | Contents |
|---|---|
| `rewrite` (this) | The new kit — Dart workspace, implementation in progress |
| `legacy-docs` | Complete documentation of the legacy codebase + the accepted design RFC |
| `main` | The legacy kit (v0.0.36), **frozen** as reference |

## Design

The architecture is fixed by the accepted RFC — read [docs/DESIGN.md](docs/DESIGN.md) before writing code. The one-paragraph version:

Design tokens (`NomoTokens`) are the only global theme. Component themes are **declared with decorators on the widget** (`@NomoThemeable` / `@Themed`) and their plumbing is generated by the **`nomo_gen` standalone CLI** (decided over build_runner). `NomoThemeData` is an **open, Type-keyed registry**, so package consumers can annotate *their own* widgets and get identical theming support — same decorators, same generated artifacts, same five-level resolution chain (constructor param → subtree override → app theme → kit defaults → token-derived defaults). Components are thin compositions over five primitives (surface, interactive, overlay engine, text core, field core).

## Workspace layout

```
packages/
  nomo_ui_kit/     # the kit (Flutter package)
  nomo_gen/        # the CLI (pure Dart, published for consumers)
docs/DESIGN.md     # the accepted RFC (canonical copy also on legacy-docs as 09-rewrite-proposal.md)
ROADMAP.md         # phased plan; Phase 0 is the current focus
```

Planned additions (not yet scaffolded): `packages/nomo_gen_builder` (optional thin build_runner wrapper), `packages/nomo_icons` (optional FontAwesome package), `example/` (gallery app, doubles as the consumer-workflow fixture).

## Getting started

```bash
flutter pub get            # resolves the whole workspace from the root
dart run nomo_gen          # CLI stub — prints planned subcommands
```

Quality gates from day one: `dart format`, `flutter analyze` (very_good_analysis), tests per package, and CI on this branch — see `.github/workflows/ci.yml`.
